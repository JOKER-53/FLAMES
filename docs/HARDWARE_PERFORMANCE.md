# Hardware loading and rendering

The original GLBs remain unchanged. `scripts/prepare-hardware.cjs` produces the default FortiGate variant from the original opaque color texture: at most 2560 pixels on its longest side, JPEG quality 92. Every geometry buffer, mesh/material relationship and socket coordinate is preserved. The source texture was 4580×4096 (~75 MB decoded RGBA); the new default is ~23 MB decoded. The generated GLB is 391,080 bytes versus 6,909,704 bytes. Inspect the original source when higher texture detail is required; no source asset is deleted or overwritten.

The preparation script also creates gzip sidecars and a content-hashed model manifest. The unchanged PA-220 is 7,117,632 bytes, or 1,943,373 bytes over gzip. Vite and the production Nginx configurations negotiate gzip and cache static assets. Content hashes in model URLs invalidate browser caches after asset changes. Generated variants/sidecars/manifest are ignored by Git and rebuilt before frontend builds/dev startup; direct Vite startup prepares them when the build helper is available. Production and development Dockerfiles include that helper. `sharp` is build-only; it is not shipped to the browser or backend runtime.

The viewer reports decoded download bytes/known percentage, then a preparation stage. Retry recreates a failed viewer; failed downloads/parses are removed from the memory cache. At most two model buffers are retained per tab, with in-flight requests shared across remounts. Each viewer parses its own scene and disposes its geometries, materials, textures, sprite resources and image bitmaps on exit. GPU context loss is reported with a retry path. Keyboard component inspection and existing socket buttons remain usable without WebGL.

Rendering pauses while the document or viewer is hidden. Static/reduced-motion views render on demand; animated views are limited to 30 fps and device pixel ratio is capped at 1.5. Input, resize, mode/cable changes and visibility restoration invalidate the view. The PA-220 loader is deferred alongside download so course-only navigation avoids its parser. The shared Three.js core remains a large lazy chunk: splitting its filename does not reduce the bytes required by the viewer. The useful reduction here is the model/texture transfer and memory footprint, deferred loader and idle rendering work.

Regression coverage checks unchanged geometry, byte reduction, bounded caching/shared transport, failed-download retry, rendering suspension/cleanup, actual software-WebGL loading, retry/cache reuse, reduced-motion idle behavior, and the no-WebGL reference fallback. Real-device frame/memory/network measurements and socket alignment remain part of acceptance; software rendering is not a hardware benchmark.
